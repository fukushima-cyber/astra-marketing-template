# Astra Marketing Template

会社・事業単位の実績、目標、施策、SNS、広告を管理する日本語のダッシュボードです。Next.js の静的フロントエンドと Cloudflare Workers / D1 / Durable Objects で構成しています。

**実績・顧客・ユーザー・接続キーは入っていません。** 新しい環境に構築するための公開テンプレートです。過去の運用リポジトリの Git 履歴も含みません。

## できること

- 会社・事業ごとの実績推移、内訳比較、CSV 取込とプレビュー
- 目標の改善進捗、ファネルの段階別実績、施策の進行状況
- SNS フォロワー・UTAGE ページの取得記録、投稿下書きの管理
- Meta 広告の数値・変更履歴、改善案件・比較実験・モデル実行履歴
- 事業・画面単位の閲覧・編集権限

データを登録・取得するとグラフが表示されます。未取得を 0 に置き換えず、日付の欠落を線で補間しません。各グラフには数値表を付けています。

## 始める

1. GitHub の **Use this template** で自分のリポジトリを作成します。運用データを扱うリポジトリには private を推奨します。
2. Node.js 22.13 以降を用意し、`npm ci` を実行します。
3. [セットアップ](docs/setup.md) に従って、自分の Cloudflare アカウントに空の D1 と Worker を作成します。
4. 全体管理者を登録し、案件・ファネル・目標とデータ接続を設定します。

`npm run dev` はフロントエンド開発用です。認証と API を含む動作確認は `npm run build` の後に `npm run preview` で行います。

## 空のフォーマット

- [business.json](templates/business.json): 事業データの空の構造。JSON インポート機能を示すものではありません。通常の登録は画面から行います。
- [analytics.csv](templates/analytics.csv): 実績取込用のヘッダーのみ。先に画面で案件・ファネルを登録し、その ID を使って記入します。
- `migrations/`: DB のスキーマ。初期レコードは会社と最初の空の事業だけです。

## 検証

```sh
npm run check:template
npm test
npm run typecheck
npm run build
```

テスト内のデータ・アカウント・キー文字列はテスト専用の架空値です。実データを入れたエクスポート、`.data`、`.wrangler`、環境変数ファイル、DB ファイルを公開しないでください。

## 外部サービスについて

外部連携には各サービスの契約・権限・接続キーが必要です。初期状態では未接続です。クラウド版の Postiz 実接続と投稿公開は未実装で、投稿下書き管理を利用できます。モデルによる診断と自律運用は、利用者が接続・実行範囲を設定した場合に利用します。モデル名は自分の API で利用できる名前を指定してください。
